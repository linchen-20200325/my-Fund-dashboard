## 1. 「一輪」是什麼 —— 本檔唯一新增的機制

### 1.1 缺口：`42` 定了**怎麼加**，沒有定**什麼時候該加**

`42` §3 把輪次的累加寫得很死，逐字是「**+1 的唯一條件**：有人**真的依 §2 重跑過一次三層程序**、
**仍**判不出來」，並且補了一句「⛔ **沒有重跑就不准 +1。**」——**這一條本檔一個字都不動，也不放寬。**

**但它沒有回答「誰會去重跑、什麼時候重跑」。** 後果是單向的：
一列 `未確認` 可以停在輪次 1 停到天荒地老，而三輪出口**永遠不會觸發** ——
那正是 `CLAUDE.md` `§8.3.P` 前言點名的形狀：**待查證沒有出口 ＝ 實質永久豁免**。

**反向檢查**（本節這個缺口宣稱可否證的地方 —— 可否證的是「那個詞在 `42` 裡怎麼被用」）：

```
git show 651bd77:docs/v2/42_live_dead.md | grep -n '輪' | grep -cE '觸發|何時|什麼時候|每當'
```

輸出：**0**（`exit=1`）。⇒ 在 `651bd77` 上，`42` 提到「輪」的行裡，
**沒有一行同時帶著上列四個時機詞**。⚠️ 這是**一條字串指令的結果**，不是「`42` 沒有定時機」的證明；
措辭換一種寫法就掃不到（同 `CLAUDE.md` `§-1.5.1c` 判定 2：**字表選錯，掃再多次都沒用**）。
**能被一條指令推翻的全稱句，本節不寫。**

**現存實例（`42` 自己表上那一列）**：`scripts/update_macro_history.py`（模組）標 `未確認`、
`未確認輪次` 記 `1`、`確認日` 2026-09-21。本檔量測日是 2026-09-29，該列**仍然是 1**。
⚠️ **這不是有人偷懶** —— 依 `42` §3，沒有人重跑就**不准** +1，那一列停在 1 是**完全合規的**。
**缺的不是紀律，是一個會讓重跑發生的事件。**

### 1.2 一輪的觸發（三種，先到先算，而且一律是被動的）

一列 `未確認` 的輪次 **+1**，只在下列事件之一真的發生、而且重跑後**仍**判不出來時：

- **觸發 (a)｜檔案被改到**：該符號**所在的檔**被任何一個 PR 改到 ⇒
  **那個 PR 的執行組**在**同一個 PR 內**依 `42` §2 重跑三層，並就地改表。
- **觸發 (b)｜所屬的頁接真資料**：該符號屬於 ui_v2 某一頁，而那一頁的接線 PR 合併 ⇒
  **該頁的實作組**重跑（母體與分工見 §2 的 S1）。
- **觸發 (c)｜有人要拿它當前提**：任何一組在派工單、規格或稽核報告裡**引用那一列去支撐下一步動作** ⇒
  **引用它的那一組**重跑。
  ⚠️ **只讀不算**：`42` §1 的查表優先允許「命中就直接用那一列的判定」，本觸發**不推翻它**；
  本觸發要的是**拿 `未確認` 去當結論用**的那一種引用 —— 而 `未確認` 本來就不是結論，
  依 `CLAUDE.md` `§-2` 規則 6，未驗的東西**不得**作為後續動作的前提。

**誰累加、怎麼累加、累加到 3 之後怎麼標**：一律照 `42` §3，本檔不重述。

### 1.3 ⛔ 三個觸發全部是被動的 —— 不得讀成巡邏授權

三個觸發的共同形狀是：**要先有一件別人已經在做的事碰到它**，輪次才會動。
**沒有任何一個觸發是「時間到了就去掃一遍」。** 這是刻意的：

- `CLAUDE.md` `§-1` 的禁止提議模式已點名「機械式清 TODO list 充數」；
- `CLAUDE.md` `§-1.5.1c` 判定 3 已釘死：**GC 是任務內的收尾義務，不是主動巡邏授權**；
- `42` §5 逐字：「⛔ **不得**引用本檔去發動一輪『全 repo 掃死碼』的巡邏」。

⛔ **不得**引用本節去立案一輪「照排程去清死碼」的工作。
本檔排的是**別的任務碰到它時要順手做什麼**，**不是**一份可以拿來開工的待辦。

## 3. 怎麼驗

### 3.1 驗收的第一條：**做的那一組不驗自己**

- `CLAUDE.md` `§-2` 規則 4：調查與稽核要獨立分派，**不可由同一組自己查自己**。
- `CLAUDE.md` `§-1.5.1` 第一條第 3 點：**實作與稽核嚴格分離，實作者不得自己驗收自己**。

⇒ 上表「誰清」與「怎麼驗」是**兩個不同的組**：登記由該母體的實作組做，
驗收一律由**品管與紅隊稽核組**執行。
⛔ **「有 QA 組」不等於「複驗做完了」**（`CLAUDE.md` `§-1.5.1a` 重點 3 第 3 點）——
總管仍須依 `§-2` 規則 3 自己查證關鍵宣稱，那是**在稽核回報之上再一層**。

### 3.2 驗收 A｜覆蓋率：**接了線的模組，它的模組層符號在表上查得到**

**做法**：對該階段母體內的每一支 `.py`，以 AST 取模組層定義的名字，
與登記表的 `檔案::符號` 欄取差集。**差集非空 ⇒ 該階段未完成。**

**為什麼要這一條**：三層確認管的是「**這一個符號**判得準不準」，
**沒有任何一層在管「有沒有符號根本沒被登記」**。漏登記的那一個**不會出現在任何一張表上**，
於是它在三道檢查下**完全沒有訊號** —— 表是綠的，因為它壓根不在表裡。

⚠️ **這一條刻意驗「差集」而不是驗「列數」**：列數對得上**不代表**成員對得上
（同 `CLAUDE.md` `§-2.A` 記載的「**數字對了不代表清單對了**」那一筆）。

### 3.3 驗收 B｜突變：**把登記拿掉，必須有東西轉紅**

**做法**：在工作樹上臨時做一次破壞，確認既有守衛**當場轉紅**，然後還原。至少兩種破壞：

- 把登記表某一列的狀態格**清空** ⇒ 讀那張表的守衛必須紅。
- 把某個已登記為 `dead` 的符號**真的刪掉** ⇒ 釘住它的守衛必須紅。

**依據**：`CLAUDE.md` `§-1.5.1a` 逐項對照表第 7 列把**突變測試**寫成內部自決區的硬要求 ——
「**拿掉修復必須能轉紅燈**」，否則那個測試根本沒守到東西。
**驗收也適用同一把尺**：一次跑完全綠的驗收，**與一次什麼都沒看的驗收，輸出長得一模一樣**。

**`46` 這一側今天已經有兩支守衛可以當突變靶**（本組實測，釘 `651bd77`）：
`tests/ui_v2/test_hld_logic.py` 的 `test_第3件正控_46登記表的每一列都記了兩個日期`
（拿掉表頭那一欄或清空任一列的登記日即轉紅，該函式的 docstring 自陳這一點），
以及同檔的 `test_0caller的常數依44第六節不刪只標`（把那幾個 0-caller 常數刪掉即轉紅）。

### 3.4 驗收 C｜輪次：**確認日與輪次必須一起前進**

**做法**：比對該列的前後兩版，`未確認輪次` +1 的同時 `確認日` 必須也換了日期。
**輪次動了而確認日沒動 ⇒ 沒有人重跑，那一次 +1 不成立**，照 `42` §3 的
「⛔ **沒有重跑就不准 +1**」退回。

⚠️ **這一條是 §1.2 唯一的把關**：三個觸發都是**靠人記得去重跑**的，

而它的終點是把一個沒人看過的符號標成 `dead（推定）`——
與 `CLAUDE.md` `§1`「錯誤的數字比沒有數字更危險」正面牴觸。

### 3.5 ⚠️ 兩張表的守衛不對稱，據實寫明（這一筆會影響驗收怎麼排）

### 5.1 零程式碼改動 —— 包含一項**本來可能需要、但本輪刻意沒做**的改動
