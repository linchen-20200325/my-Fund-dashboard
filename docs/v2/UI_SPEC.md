### 3.1 ⭐ 狀態模型是 **五態**，不是三態 —— 這是本檔必須更正上游的第一件事

### 3.2 三態（五態）的使用規則 —— **可判定，不是「視情況」**

#### 3.2.1 客戶已拍板的「三問判準」（2026-08-28，v2 沿用不另發明）

本 repo 已有一套客戶拍板的決策程序，就地記載於 `ui/tab_fund_grp_health.py`
與 `ui/helpers/fund_grp_health/backtest_section.py`。**v2 逐字沿用**：

```
問一｜這個區塊該不該在這裡，是固定的還是取決於資料？
      · 固定（骨架的一格）           → 往下問
      · 取決於資料（每檔一個的展開區） → 資料沒有就不畫，不留占位

問二｜使用者為了看到它，已經做過那個動作了嗎？
      · 已經按過／已經等過           → **一律留灰色占位 ＋ 缺什麼 ＋ 去哪裡補**
      · 還沒按                       → 不加冗餘占位（客戶：「按鈕前不加冗餘占位」）

問三｜它為什麼沒東西？
      · 還沒給資料（之後會有）       → **⬜ not_ready()**
      · 結構上不適用（本來就不存在） → **➖ NOT_APPLICABLE_MARK**
      · 手上有 Exception             → **🔴 system_error()**（型別層強制，見下）
```

#### 3.2.2 三條硬邊界（型別層或守衛強制，不靠自律）
