## 4. Unique Owner 與 active Sheet SSOT（客戶已裁示方向）

| 能力 | 唯一擁有頁 | 其他四頁（🌍／⚖️／💼／🔍） |
|---|---|---|
| Google login／logout、切換帳號、account status | ⚙️ | 不放任何登入元件；最多顯示一行摘要並指回 ⚙️ |
| Sheet listing（列出目前帳號可存取的試算表） | ⚙️ | 不列清單 |
| Sheet selection（清單選擇＋URL／ID 次要入口） | ⚙️ | **不放 selector**（💼 也不放第二個） |
| active Sheet（目前使用中的那一本；一次只有一本） | ⚙️（唯一寫入者＝使用者在 ⚙️ 的明確操作） | **只讀 active Sheet 的結果**；active 未設定／未驗證時照實顯示「⬜ 尚未選定試算表」類狀態並指回 ⚙️，不自己猜、不自己換、不退回別本 |
| connection diagnostics（連線／權限／新鮮度／原文） | ⚙️ | 只顯示 freshness 標記 |

**Currently Active 與 Pending Selection（寫死）**
- **Active**＝第 4 節的唯一 active Sheet SSOT；只有「［使用這一本］→ 驗證成功」會改它。

- 下拉選完**不得**自動切換（避免誤觸）；下拉選到的就是目前使用中那一本時，不出現 Pending 區與［使用這一本］。
- 驗證三步（〔文件組擬定〕）：確認帳號仍有權限 → 確認試算表可讀 → 確認必要條件（必要分頁等，實作時另定）。失敗結果至少分：⛔ 無權限、⛔ 找不到、◷ 登入已過期、⬜ 無法判定、⛔ 驗證失敗；**失敗一律維持舊 Active**，不轉成成功、不轉成空值、不清掉舊 Active（◷ 登入已過期例外：舊 Active 改成「上次使用（未驗證）」，比照 G-13 的處理，因為登入已失效，本來就不能再當有效連線。⚠️ **此例外是文件組讀法，可被客戶推翻**：客戶原話只說「失敗維持舊 active」；G-13 原本講的是登出，套用到驗證中途登入過期是本組的推論）。
- **搜尋**：只在已取得的清單內過濾名稱，**不新增資料源、不另做 search engine、不另打任何 API**；實作時**優先評估 Streamlit 原生 selectbox 的輸入過濾**是否已足夠（本批不實作）。

- 現在持倉那本試算表綁死在部署設定（`POLICY_SHEET_ID`），畫面上不能換（62 §1 D2）。您 2026-10-22 指示：未來要能切換不同的已授權 Sheet，**不得把目前這本帳本設計成永久唯一來源**（BL-0392，待裁示）。
- BL-0381 第 (6)(7) 步：**只有您明確操作才切換，不得自動改用其他 Sheet**。

**現行裁示與護欄**
- 同第 6 節：B 線只讀取保單／帳本（客戶 2026-09-21、2026-10-13）；`DEC-2026-10-17-03` 護欄 4 不授權改 T6 與正式寫入架構。
- T6：客戶 2026-09-27 核准「保單那一本」（49 第 6.2 節），加上總管技術裁定「ui_v2 只讀 secret `POLICY_SHEET_ID`、不退回 session」（58 第 13 節 (6)）。
- 現行寫入只會寫到設定試算表（`SETTINGS_SHEET_ID`）那一本（58 附錄 B-G）。
- 新增設定鍵或分頁屬資料契約變更，走 50／44 修正程序；「哪一本是持倉來源」屬資料身分（data identity），在 v1.0 Stop／Decision Gate 清單內（`DEC-2026-10-16-03`）。
