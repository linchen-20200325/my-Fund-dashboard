### (a-1) 層次搬動（`HLD-1`→③、`EXP-2`／`EXP-3`→④、`ALO-1`→④，`ALO-3` 定位）

- **問題**：要不要照 59 把這幾塊從「關鍵數字」區移走？這會改變使用者打開頁面時第一眼看到的內容：持倉頁先看到偏離，探索頁先看到條件與結論，配置頁先看到目前和目標的差距。
- **選項 A**：照 59 搬；`ALO-3` 定為 ②（卡片本體留在 ②、預設只畫［開始試算］入口，進入後顯示模擬畫面）。44 要連帶改寫的條文：
  1. 第三節持倉體檢、標的探索、資產配置三張層表；
  2. 逐頁補一行「③ 由哪一塊的哪個結果撐起」（第七節第三小節之七其一第 2 條交辦的事）；
  3. 第二節硬規則第二條（初次載入展開 1 枚結論燈與 3 張核心卡）——搬動後持倉頁②剩 2 張、探索頁②剩 1 張（`EXP-1`）、配置頁②剩 2 張；
  4. 第二節節判準（展開塊數的驗法）；
  5. 第七節第三小節之七其一第 3 條（「展開的塊照舊是 1 枚結論燈與 3 張核心卡」）；
  6. 第五節第四小節展開區規則與元件判準中引用「3 張核心卡」之處（隨實作批逐處核對）。
- **選項 B**：都不搬，只寫 ③ 的來源（③ 照樣顯示已算出的項目，但卡片仍留在②）。
- **總管推薦與理由**：**A**。這些搬動只動呈現位置，不改任何計算、門檻或資料來源，符合「不因 UI 改版改動資料層或投資 business rules」這條執行限制。59 方向已經核准；選 B 的話，偏離會在②和③各出現一次，違反 44 第三節「一頁只回答自己那一句」的邊界。`ALO-3` 留在 ② 是因為 59 把入口畫在 ②，且試算不是證據也不是設定。
- **風險**：
  1. 上列第 3～6 項若漏改一處，規格會自相矛盾；凍結不變量（塊數、判準行數）不變，但守衛測試釘住的雜湊要同步。
  2. `ALO-1` 移到 ④ 以後，第一次使用、還沒設定目標的人得先展開 ④ 才找得到輸入欄；59 第 5.4 節「尚未設定目標」那一格需要放導覽或展開按鈕。

### (a-2) `○ 已檢查・正常`（持倉 ① 四計數、資產配置 59 第 5.3 節）

- **問題**：持倉頁的結論要不要改成「持有 n／◆ m／○ k／⬜ j」四個數？資產配置全在帶內時要不要寫「○ 已檢查・正常」？
- **選項 A**：兩頁都採用 `○ 已檢查・正常`，寫進 44；條件是所有門檻都已設定、資料齊全、實際比對過且未超出；資料不足一律算 `⬜`。
- **選項 B**：不寫 `○` 與「正常」。持倉 ① 只放三個數（持有、◆、⬜）；資產配置全在帶內時沿用 44 `ALO-0` 現行文案描述事實（各類別皆在容許帶內），不加「正常」。
- **總管推薦與理由**：**B**。44 第七節第三小節之七其四第 5 條已明文寫過，`○ 已檢查・正常` 不在八題裁示字面內。把「沒超出自設門檻」說成「正常」，容易被讀成投資判斷（58 U-12 要防的方向，也可能落在 Gate「會改變投資判斷的呈現」）。持倉「正常」的數＝持有 − ◆ − ⬜，使用者自己算得出來。
- **風險**：59 第 3.1、5.3 節要回修。選 A 等於新增一個評估狀態，`○` 的觸發條件若定義不嚴，會把「規則還沒設定」算進「正常」。

### (a-3) 市場總覽 ③「變化大不大」

- **問題**：59 在市場總覽 ③ 放了一行「變化大不大：⬜ 無法判定（規則未設定）」。要不要寫進 44？
- **選項 A**：寫進 44，只寫這句固定的「無法判定」文案，不定義任何門檻。
- **選項 B**：44 只寫 ③ 的資料面那一行；「變化大不大」整行不畫，等真的有門檻時再一起提案。
- **總管推薦與理由**：**B**。目前沒有任何核准的「變化大」門檻；訂門檻屬於 Gate「正式 threshold 的值或語意」。先畫一行永遠是「無法判定」的字不能回答問題，還等於預先占好門檻的位置。
- **風險**：59 第 2.1 節要回修；選 A 的話，日後可能有人把這行當成已核准功能直接填門檻。

### (a-4) 市場總覽 ①「✓ 三張卡的資料齊」與 ③「資料面：沒有例外」

- **問題**：市場總覽要不要用 ✓ 與「沒有例外」這類「一切正常」的字樣？與 (b-2) 設定頁的 ✓／「其餘正常」同一類。

- **選項 B**：① 沿用 44 `MKT-0` 現行燈與文案（只描述三張卡各自的資料狀態），不加 ✓；③ 沒有資料面例外時，資料面那一行不畫（44 第七節第三小節之七其一第 2 條：沒有項目時不為了有內容而列），不寫「沒有例外」。

- **風險**：59 第 2.1 節要回修；頁面在沒有例外時看起來比較「空」。

## (b) P1-⑥ 設定與診斷頁重排

> ⚠️ **本組特別標明**：(b-1) 和 (b-3) 會改變「什麼時候、去抓哪些資料」，**可能觸及**裁示執行限制「不因 UI 改版改動資料層」。這兩題本組都推薦保守選項。

### (b-1) 新按鈕［更新需要更新的資料］

- **背景（三份文件說法不一）**：
  - 已核准的 58 U-46：「預設只更新需要更新的資料；『強制重新取得』只放 SET 進階診斷；MUST NOT 改 production 取數政策（TTL、冷卻、來源優先序）」。
  - 已核准的 58 第 8 節 SET 列：主要按鈕為［更新需要更新的資料］（取數類）。
  - 44 現行只有 `SET-5`「重新取數」（使用者選層級，按一次抓一層），沒有這顆按鈕；且依 59 檔頭與本檔位階，三者不同時以 44 為準。
- **問題**：要不要在 44 新增［更新需要更新的資料］，按下去只抓「延遲」或「缺」的那幾類？
- **選項 A**：照 58／59 新增，作為主要按鈕；按鈕自己判斷哪幾類過期，再對那幾類發出取數。
- **選項 B**：不新增。保留 44 現行 `SET-5`（它原本就是層 3，四段制下已在 ④「操作」，不需搬動）；① 的狀態句旁加一枚導覽，直接跳到 `SET-5`。同時在 58 U-46 與第 8 節 SET 列就地加註收斂：「主要按鈕」讀作 `SET-5`，「預設只更新需要更新的資料」暫不落地，待另行裁示。
- **總管推薦與理由**：**B**。理由兩條：
  1. **44 優先**：58／59 都自陳不凌駕 44，44 沒有寫的取數入口不能因為原則檔寫了就直接做。
  2. **取數語意屬資料層護欄**：選項 A 要新增一段「哪一類算需要更新」的判斷並由它觸發取數，等於把 `SET-1` 的新鮮度判定（使用者自設上限）變成取數觸發條件，屬於改變取數語意，碰到「不因 UI 改版改動資料層」的執行限制。選 B 不新增任何取數路徑，`SET-5` 的寫入範圍（`fetch_log` 和該層級資料表）完全不變。
- **風險**：選 B 的便利性比 59 差，59 第 6 節與 58 U-46、第 8 節都要加註收斂（只加註，不劃掉核准原文）。選 A 的話，上限設得短時每次進頁都可能觸發大量取數，撞上來源冷卻機制。

### (b-2) SET 版面重排：`SET-2`／`SET-3` 移到 ④、②新鮮度表、①文案

- **問題**：要不要照 59 把來源健康卡（`SET-2`）、規則參數卡（`SET-3`）移到 ④，同時把②改成「淨值／配息／市場指標／其他」四列並使用 ✓／◷／◇，① 改成「◷ n 類資料延遲，其餘正常」？
- **選項 A**：全部照 59。
- **選項 B**：`SET-2`、`SET-3` 照 59 移到 ④；②改用 ◷／◇，但**不用 ✓**（沒有延遲也沒有缺的列只寫「最近取得 MM-DD」）；①改寫成「◷ n 類資料超過你設的上限」，**不寫「其餘正常」**；新鮮度表暫維持 44 現行三列。
- **總管推薦與理由**：**B**。搬卡和換符號屬呈現層，可以接受。但：
  1. ✓ 和「其餘正常」不在八題裁示字面內（其四第 5 條）；上限沒設時 44 `SET-1` 規定比較欄是「不適用」，寫「正常」會把尚未評估說成正常（58 U-12）。
  2. `SET-1` 現行三列；59 加的「其他」那一列，44 `SET-1` 的「來源」欄沒有對應的新鮮度欄位，硬上會一直顯示 ◇。第四列另立登記，定義來源後再上。
- **風險**：`SET-1` 判準（「上限設 0，三列都是外，`SET-0` 的 N 等於 3」）綁定三列；選 A 會牽動判定，碰到護欄 2。

### (b-3) 強制重新取數放進「進階診斷」

- **背景**：已核准的 58 U-46 明訂「『強制重新取得』只放 SET 進階診斷」，59 第 6.2 節照畫「強制重新取得（選層級）［取數］」。但 44 第七節第三小節之七其二第 8 條明文：進階診斷是呈現層，**不新增取數、不寫入**。兩者直接衝突，依位階以 44 為準。
- **問題**：要不要修改 44 其二第 8 條，允許進階診斷內有一顆取數按鈕？
- **選項 A**：修改其二第 8 條，照 58 U-46 放入。

## (c) 總管內部決定，告知客戶（不需裁示）

### (c-1) 「尚未設定設定試算表」框（59 第 6.3 節）

- **決定**：44 補 `SET-0` 的一種空狀態「⬜ 無法判定：尚未設定設定試算表」；不寫「需要先在部署設定填入設定試算表」這類操作指引。
- **理由**：錯誤文字只描述狀態、不指示動作，沿用客戶 2026-10-02、2026-10-03 既有裁示（44 第七節第三小節之七其五第 2 條轉述）。
- **「其他四頁的存檔與取數紀錄暫停」是不是事實（本組 2026-10-17 讀碼查證）**：
  - `repositories/settings_sheet_repository.py::settings_sheet_id` 在 `SETTINGS_SHEET_ID` 未設定時一律拋 `SettingsSheetError`，`code="not_configured"`，訊息是同檔常數 `NOT_CONFIGURED_MESSAGE`＝「未設定試算表 ID，暫停寫入」。
  - 同檔 `_run`（讀與寫共用的開表入口）第一步就呼叫 `settings_sheet_id`，所以經由這個 repository 的**讀與寫都會失敗**，不會打到上游。
  - `ui_v2/set/live.py` 把 `not_configured` 列入 `_NOT_WRITTEN_CODES`（判為「未寫入」）；`ui_v2/plain.py`、`ui_v2/health.py` 把這句訊息歸到「尚未設定」那一族顯示。
  - 因此「經設定試算表存檔與寫取數紀錄的動作會被拒絕、不寫入」是有程式依據的事實；但本組**沒有逐頁確認四頁的每一個存檔動作都走這個 repository**（例如 `repositories/policy_supplement_repository.py` 另有自己的 `NOT_CONFIGURED_MESSAGE`）。故 44 只寫狀態句，不寫「四頁全部暫停」這種全稱描述。
