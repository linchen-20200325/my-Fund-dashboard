一、要拍板的那一句（逐字）

資產配置頁接上真資料後，正式模式三枚「存檔」按鈕停用，停用原因（滑鼠停留時顯示的 help）逐字為：

存檔寫入端尚未接上，這一輪只讀不寫

本頁只送這一句。客戶已砍掉原提案的後半句「按了不會存下任何東西」，理由逐字：
「後半句在 alo 是誤導 —— alo 根本沒有寫入端，『按了不會存』暗示『有存但不會持久』，實際是沒有存這個動作。」

二、這一句會出現在哪三枚按鈕上

三枚都叫「存檔」（logic.TEXT_SAVE），分屬三個不同的塊，不在同一個地方：

塊塊名層同一塊裡的鄰居
ALO-1目標輸入卡層 2只有這一枚（不畫新增類別鈕）
ALO-3情境試算卡層 2輸入零列時另有一枚「新增假設」
ALO-4分組定義層 3一枚「前往 Sheets 維護持倉」（恆在）

出處：ui_v2/alo/logic.py 的 _build_alo1 / _build_alo3 / _build_alo4， 三處都是 _button(TEXT_SAVE, "存檔", keys=keys)。塊名與層別取自同檔 BLOCK_TITLES / BLOCK_LAYERS。

停用是資料驅動的，不逐枚寫死：ui_v2/alo/live.py::apply_live_notes 走過整棵模型， 凡 button["_writes"] 非空就停用並填原因；而 logic._BUTTON_WRITES 裡只有「存檔」對到 {"user_setting"}， 其餘七種按鈕都是空集合。所以「三枚」是這條規則的結果，不是一份人工清單。

三、為什麼要停用

這一輪接線只接讀、不接寫：資料從 L2 進來畫得出畫面，但存檔的寫入端還沒接上。 若按鈕照舊可按，使用者按下去之後畫面不會有任何反應，也不會有任何東西被存起來 —— 那正是 CLAUDE.md §1 明文禁止的「讓流程看起來成功」。 停用並寫出原因，是把「這件事現在做不到」誠實講出來，而不是讓按鈕假裝它還在工作。

接上寫入端之後，這段停用邏輯與這一句文案都應該整段拿掉，不是留著改字。

四、為什麼不沿用市場頁那一句（這一段有實測）

市場頁 ui_v2/mkt/live.py 的 SAVE_DISABLED_REASON 是：

設定存檔尚未接上，存了也留不到下次開頁

實作時這一句被整句複製到資產配置頁（ui_v2/alo/live.py 的註解逐字寫著 「與 ui_v2/mkt/live.py 逐字相同的一句（沿用，不另編一句）」）。 但它在市場頁為真、在資產配置頁為假，差別在一個可以量的機制： 

$ for f in ui_v2/mkt/page.py ui_v2/alo/page.py; do \
    printf '%s: ' "$f"; git show 6c78294:$f | grep -c "on_click=" || true; done
ui_v2/mkt/page.py: 2
ui_v2/alo/page.py: 0

市場頁那兩枚按鈕真的掛了寫入函式，而且它真的寫得進去： 

$ git show 6c78294:ui_v2/mkt/page.py | grep -n "_user_setting"
258:    store = st.session_state.setdefault("_user_setting", {})
300:        store = {} if live_mode else st.session_state.get("_user_setting", {})
市場頁資產配置頁
按鈕掛寫入函式有（2 處）沒有（0 處）
按下去發生什麼寫進當次連線的暫存區沒有這個動作
關頁再開寫過的東西不見了本來就沒有寫過
「存了也留不到下次開頁」為真為假
客戶砍掉後半句的理由，正好對上這張表：「存了也留不到下次開頁」與「按了不會存下任何東西」 都暗示有一個存的動作、只是留不住。在市場頁確實如此；在資產配置頁 連那個動作都不存在。照抄等於把一句在別頁為真的話，搬到這一頁變成假話。

⚠️ 這一處不是讀程式碼讀出來的，是獨立稽核跑了計數才抓到 —— 複製過來的那一句在字面上完全合理，沒有人在複製的當下發現它換一頁就不成立。 下一個要把某一頁的文案搬到另一頁的人，請先量一下那句話依賴的機制在新的那一頁存不存在。

五、哪些按鈕不停用（正例）

依 CLAUDE.md §-2.A 第 3 款，禁令要同時寫出正例，否則會被讀成「全部都不能按」。 下列三枚照常可按，因為它們不寫 user_setting：

按鈕塊種類本案是否停用
匯出ALO-5 試算結果匯出匯出不停用
前往 Sheets 維護持倉ALO-4 分組定義導覽不停用
新增假設ALO-3 情境試算卡新增列不停用
⚠️ 「匯出」另有一條既有的停用規則，與本案無關，兩者不要混為一談。
畫面上無列時「匯出」本來就會停用，原因是「目前沒有可匯出的列」 （logic.TEXT_NO_EXPORT_ROWS）。那是本來就有的行為， 在示範模式與正式模式都一樣，不是這一輪因為寫入端沒接上才加的。 本案只動會寫 user_setting 的那三枚；「匯出」那一條一個字都沒改。

（例如沒改過的表單算不算「可存」）		後端還沒接上，所以現在存不了
