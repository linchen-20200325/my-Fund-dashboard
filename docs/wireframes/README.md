# UI 線框（Wireframes）—— 客戶拍板原件

本目錄存放**客戶審核並拍板的 UI 線框圖**。它們不是設計參考、不是草圖說明，
而是**規範文件（normative）**：production code 直接引用其中的條文，並以它為實作依據。

---

## ⚠️ 這些是客戶原件，不得改寫、不得「優化」

- **禁止**修改、重排、精簡或「順一下文字」。逐字保留。
- 日後客戶若給新版 → **新增檔案**，並在下方「版本關係」註明它取代／延伸了誰。
  **不要覆蓋舊檔** —— 舊檔是拍板紀錄，覆蓋掉就失去了「當初客戶同意的是什麼」這個事實。

依 `CLAUDE.md §-1.5`（虛擬軟體公司運行規範）v3 `03`-2 ①：
任何版面佈局、欄位增減或分頁動線異動，動工前必須先提線框草稿供客戶拍板。
本目錄即該流程的**產出物與存證**。

---

## 為什麼這些檔案必須進版本控制

在此之前，這三份線框**只存在於 session 的暫存目錄**（gitignored，且容器回收即消失），
但 repo 內的 production code 已經在註解裡逐字引用它們。

**引用一份不在版控裡的檔案，等於引用一份會消失的規範。**

一旦暫存目錄被回收，那些引用就全部變成**指向不存在文件的路徑引用** ——
而這正是本 repo 近期已經用兩個 PR 修過的同一種病。與其日後再修一次，
不如把被引用的原件本身放進版控。

**實測引用範圍（量測日 2026-08-28，`grep -rlE '線框|[Ww]ireframe' --include=*.py`）**：

| 範圍 | 命中 |
|---|---|
| production `.py`（不含 `tests/`） | **26 處，11 檔** |
| 全 repo `.py`（含 `tests/`） | 55 處 |
| 逐字引用**檔名**者 | `ui/helpers/render_state.py`、`tests/test_render_state_color_separation.py`、`tests/test_app_apptest.py` |

⚠️ 上表是**會漂移的量測值**，依 `CLAUDE.md` 慣例標註量測日；需要現值請現場重跑上列指令，
**不要引用本表**。

最強的依賴是 `ui/helpers/render_state.py` —— 其 module docstring 寫明
「線框原文，**本模組存在的唯一理由**」，並逐字引用
`fund-empty-state-wireframe.html` §03「顏色：三態統一規則」。
**該線框若消失，這個模組就失去它自稱的存在依據。**

## 各檔用途

| 檔案 | 日期 | 內容 | 狀態 |
|---|---|---|---|
| `fund-wireframe-final.html` | 2026-08-27 | **七分頁重整為五分頁**的結構線框（分頁動線異動） | 客戶已拍板 |
| `fund-empty-state-wireframe.html` | 2026-08-28 | **空狀態與三態顏色規則**；§03「顏色：三態統一規則」嚴格分離「業務紅燈」與「系統真紅燈」 | 客戶已拍板，**批次 3a 已依此上線**（`ui/helpers/render_state.py` 直接引用其 §03） |
| `fund-redesign-wireframe.html` | 2026-08-27（早期） | 早期改版草稿 | **保留供追溯**，非現行規範 |

### 版本關係

- `fund-redesign-wireframe.html` → `fund-wireframe-final.html`：後者是前者定案後的版本。
  **現行結構規範以 `-final` 為準**；`-redesign` 保留是為了追溯「當初考慮過什麼、為什麼沒選它」。
- `fund-empty-state-wireframe.html` 與上述兩者**正交**：前兩者管**版面結構**（哪些分頁、怎麼排），
  它管**狀態呈現**（沒資料時畫什麼、什麼情況用什麼顏色）。**三份都有效，不互相取代。**
