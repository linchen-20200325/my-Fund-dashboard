# UI 線框（Wireframes）—— 客戶拍板原件

本目錄存放**客戶審核並拍板的 UI 線框圖**。它們不是設計參考、不是草圖說明，
而是**規範文件（normative）**：production code 直接引用其中的條文，並以它為實作依據。

---

## ⚠️ 這些是客戶原件，不得改寫、不得「優化」

- **禁止**修改、重排、精簡或「順一下文字」。逐字保留。
- 日後客戶若給新版 → **新增檔案**，並在下方「版本關係」註明它取代／延伸了誰。
  **不要覆蓋舊檔** —— 舊檔是拍板紀錄，覆蓋掉就失去了「當初客戶同意的是什麼」這個事實。

依 `CLAUDE.md §-1.5`（虛擬軟體公司運行規範）v3 `03`-2 ①：
任何版面佈局、欄位增減或分頁動線異動，動工前必須先提線框草稿供客戶拍板。
本目錄即該流程的**產出物與存證**。

---

## 為什麼這些檔案必須進版本控制

在此之前，這三份線框**只存在於 session 的暫存目錄**（gitignored，且容器回收即消失），
但 repo 內的 production code 已經在註解裡逐字引用它們。

**引用一份不在版控裡的檔案，等於引用一份會消失的規範。**

一旦暫存目錄被回收，那些引用就全部變成**指向不存在文件的路徑引用** ——
而這正是本 repo 近期已經用兩個 PR 修過的同一種病。與其日後再修一次，
不如把被引用的原件本身放進版控。

**實測引用範圍（量測日 2026-08-28，`grep -rlE '線框|[Ww]ireframe' --include=*.py`）**：

| 範圍 | 命中 |
|---|---|
| production `.py`（不含 `tests/`） | **26 處，11 檔** |
| 全 repo `.py`（含 `tests/`） | 55 處 |
| 逐字引用**檔名**者 | `ui/helpers/render_state.py`、`tests/test_render_state_color_separation.py`、`tests/test_app_apptest.py` |

⚠️ 上表是**會漂移的量測值**，依 `CLAUDE.md` 慣例標註量測日；需要現值請現場重跑上列指令，
**不要引用本表**。

最強的依賴是 `ui/helpers/render_state.py` —— 其 module docstring 寫明
「線框原文，**本模組存在的唯一理由**」，並逐字引用
`fund-empty-state-wireframe.html` §03「顏色：三態統一規則」。
**該線框若消失，這個模組就失去它自稱的存在依據。**

### 版本關係

- `fund-redesign-wireframe.html` → `fund-wireframe-final.html`：後者是前者定案後的版本。
  **現行結構規範以 `-final` 為準**；`-redesign` 保留是為了追溯「當初考慮過什麼、為什麼沒選它」。
- `fund-empty-state-wireframe.html` 與上述兩者**正交**：前兩者管**版面結構**（哪些分頁、怎麼排），
  它管**狀態呈現**（沒資料時畫什麼、什麼情況用什麼顏色）。**三份都有效，不互相取代。**
- `rotation-components-wireframe.html` **對 `fund-wireframe-final.html` 做了一處明確覆蓋**
  （客戶 2026-08-31 **Q3 裁示**）：`-final` 中「批次端輪動配對**整段移除**、只留 ②」該句
  **自此不再是現行規範** —— ③ 保留輪動能力、改型為「互補配對探索」
  （預設收合 Expander + 最佳配對卡 + 完整表 + CSV）。
  依本 README 開頭規定，**`-final` 檔案本身一字未改**（客戶原件、拍板紀錄）；
  覆蓋關係記在這裡，現行以 `rotation-components-wireframe.html` 第 03／07 節（Q3）為準。
  其餘部分兩份**互不取代**：`-final` 管五分頁整體結構，本份只管輪動配對兩元件。

- **2026-08-31 的三份新線框（`wireframe-macro-health` / `wireframe-fund-research` /
  `policy-split`）與 `fund-wireframe-final.html` 的關係：細部延伸，不是取代**（唯一例外見下一條）。
  `-final` 定的是**五個分頁怎麼分、誰去誰留**（跨分頁的結構）；這三份各自往下鑽一層，
  定的是**某一頁裡面的區塊怎麼排、哪些重複要收**（頁內的資訊架構）。
  三份的守備範圍互不重疊，合起來剛好蓋滿五個分頁：

  | 新線框 | 管哪幾頁 | 它回答的問題 |
  |---|---|---|
  | `wireframe-macro-health.html` | **① 市場定調 · ② 組合健診** | 這兩頁各自該留什麼、哪些區塊該互搬 |
  | `wireframe-fund-research.html` | **③ 基金研究** | `-final` 決定「個基深掘 + 批次分析 → 合併成 ③」之後，**合併頁本身長什麼樣** |
  | `policy-split-wireframe.html` | **④ 我的配置 · ⑤ 設定與診斷** | `-final` 決定「配置留 ④、設定搬 ⑤」之後，**那 800 行保單區實際怎麼切** |

  → 讀的順序是：**先讀 `-final` 知道有哪五頁，再讀對應那一份知道該頁裡面怎麼排。**
  `-final` 本身**除下一條所列的那一處外，其餘一字未被推翻**。

- `wireframe-fund-research.html` **承接** `rotation-components-wireframe.html` 的 Q3 結果，
  兩份**不衝突**：Q3 決定「③ 批次端的輪動配對改型為『🧩 互補配對探索』（預設收合 Expander +
  最佳配對卡 + 完整表 + CSV）」，而 `wireframe-fund-research.html` 的現況盤點（§01 模式 B）
  **就是照這個改型後的樣子畫的**。同理 `wireframe-macro-health.html` 的 DUP-7 判定
  「🛡️ 持倉互斥避險（摘要）留 ② 原位、⑥ 相關性矩陣（明細）不搬家」也與 Q1／Q2 一致。
  **三份併讀，無矛盾。**

- ⚠️ `policy-split-wireframe.html` **對 `fund-wireframe-final.html` 做了一處明確覆蓋**
  —— **有意識的變更，不是漏改**（日期 **2026-08-31**，決策者 **AI 總管**，依客戶當日授權的
  「Tab 內容重分配全權」；客戶其後看過該線框並回覆「版面 OK，動工」）。

  **衝突點**：**保單資料的唯讀檢視（保單一覽 + 每張保單明細）到底住哪一頁。**

  | 線框 | 核准先後 | 該線框怎麼寫 |
  |---|---|---|
  | `fund-wireframe-final.html` | **先** | ⑤ 設定與診斷「B · 🗄️ 資料維護」搬入「🛠️ 進階工具（保單資料表檢視）」，並註明**這裡只留唯讀檢視與批次工具** |
  | `policy-split-wireframe.html` | **後** | 保單一覽與每張保單明細**留在 ④ 我的配置**（該線框的「決定 A」） |

  **兩邊理由並陳（舊寫法沒有寫錯，是被權衡掉的）**：
  - **舊寫法的理由仍然成立** —— 設定性質的東西集中到 ⑤，④ 就能保持乾淨、動線單純；
    而「唯讀檢視」跟著「保單資料表」一起搬，分類上也自洽。
  - **被權衡掉的原因有兩個**：(a) ④ 的「配置總覽 → 保單分組」**本來就是按保單分組呈現的**，
    把明細切到另一頁，等於**把同一件事拆成兩頁對照著看**；(b) 保單明細是**每個月都會看的資料**，
    不屬於 ⑤「出事才來查」的定位。
  - **以後核准者為準**：客戶是在**看過** `policy-split-wireframe.html`（該線框首屏就用紅框
    把這項不一致標示出來，並附「可以直接否決」的說明）**之後**才說「版面 OK，動工」。

  依本 README 開頭規定，**`-final` 檔案本身一字未改**（客戶原件、拍板紀錄）；
  覆蓋關係記在這裡。**現行以 `policy-split-wireframe.html` 的決定 A 為準。**
  ⚠️ **這一條務必讀到** —— 兩張線框對同一塊內容給了相反的位置，
  不知道哪張算數的人，很可能把它當成漏改而「修正」回 ⑤。
  兩份其餘部分**互不取代**：`-final` 管五分頁整體結構，`policy-split` 只管保單區的切分。
