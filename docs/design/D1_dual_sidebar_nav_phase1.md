## 0. 結論先講（給客戶的一段話）

1. **D1 的第一層五類，和客戶已核准的「長期五頁」（🌍市場與趨勢／⚖️資產配置／💼我的持股／🔍找基金／⚙️設定）完全同一組**（`PROJECT_RULES.md` 13.2 第 1 條、`DEC-2026-10-26-01`）。五類各對應現有 B UI 的一頁（mkt／alo／hld／exp／set），不需要新增第六類。**【事實】**
2. **第二層是真正的難題：現有 B UI 每一頁都是「一頁到底」的單一 Streamlit 頁**（①結論→②關鍵數字→③需要注意→④詳細資料），**沒有任何一頁已經被拆成子頁**。客戶範例的 18 個子頁名稱裡：**只有 1 個是整頁、其餘是「頁內的卡片或區塊」或「根本沒有對應功能」**（見第 3 節）。**【事實】**
3. **有 4 個範例名稱查無對應功能（⬜ 無對應功能）**：台股趨勢、國際趨勢、風險觀察、再平衡。其中「台股趨勢」是客戶 2026-10-23 自己裁示移除的方向（`DEC-2026-10-23-01`）、「再平衡」與 44 第三節 3.0 資產配置頁邊界「不產生再平衡動作」直接牴觸。**不硬湊。**
4. **Streamlit 1.59 的原生 `st.navigation` 表達不出「選第一層、第二層只顯示該類子頁」**：原生只有「分組標題＋頁清單」（側欄全展開）或「頂部下拉」；且頁數超過 12 時側欄會收成「View X more」。要做 D1 必須 `position="hidden"` 後**自己用 `st.page_link` 畫側欄**。**【事實：已讀 1.59.2 原始碼；見第 7.3 節】**
5. **AI 總管推薦：方案 A「殼層先行」**——Phase 1 只做**雙層側欄殼層**（第一層五類固定、第二層顯示該類「真實存在」的入口），**不拆頁、不動 44 內文、不增減任何功能**；第二層的「頁內區段跳轉」先做可行性驗證，驗過才上。**要把客戶範例的子頁真的拆成獨立頁（方案 B）屬另一個 Decision Gate，且牽涉 44 解凍**，建議在客戶看過方案 A 的實機後，**逐類**另案決定。
6. **有三處和凍結的 44 衝突，已另列為「解凍 Decision Gate」，本檔不改 44**（第 7.4 節）：頁序、頁名（市場總覽 vs 🌍市場與趨勢 等）、以及（方案 B 才有）「一頁十塊／四層」結構。

## 2. Wireframe（文字線框；`‹…›` 為示意，非真實資料；名稱為暫名，待客戶定字）

### 2.1 桌機（≥1280，三個斷點見 44 第二節 2.1）

單一側欄、上下兩段（第一層在上、目前分類的第二層緊接在該類下方展開）。**【推論】** 單一 `st.sidebar` 疊放兩層可行；另一種排法是把第二層放在主內容區左側窄欄，本草稿推薦前者（手機抽屜同一結構、少一個版面斷點）。

```text
┌──────────────────────┬──────────────────────────────────────────────────────────┐
│ 基金儀表板            │ 🌍 市場與趨勢 › 市場總覽                資料截至 ‹MM-DD› │
│ （B 線預覽・非正式站）│ ─────────────────────────────────────────────────────── │
│ ─────────────────── │ ① 結論                                                   │
│ 🌍 市場與趨勢  ◀ 目前│   ‹一枚結論燈＋一句話›                                    │
│    ● 市場總覽        │                                                          │
│    ○ ‹區段跳轉 1›    │ ② 關鍵數字                                               │
│    ○ ‹區段跳轉 2›    │   ┌──────────┐ ┌──────────┐ ┌──────────┐               │
│ ⚖️ 資產配置          │   │ 風險情緒  │ │ 景氣位置  │ │ 資金匯率  │               │
│ 💼 我的持股          │   └──────────┘ └──────────┘ └──────────┘               │
│ 🔍 找基金            │                                                          │
│ ⚙️ 設定              │ ③ 需要注意      ‹只列本頁已算出的例外，沒有就不列›          │
│                      │ ④ 詳細資料（預設收合）                                   │
│                      │                                                          │
```

- **第一層**：五類永遠可見、固定順序（客戶簡報順序，見 §7.4 與 44 的頁序衝突）；目前分類以「◀ 目前」文字＋粗體標示，**不只靠顏色**。
- **第二層**：只展開目前分類；其他四類只顯示類名。**切換分類 ＝ 1 次點擊（第一層）＋ 1 次點擊（第二層）＝ 2 次**；若某類只有 1 個第二層項目，點第一層直接進入（1 次）。
- **頁首麵包屑**「🌍 市場與趨勢 › 市場總覽」是主內容的第一行，手機與桌機同一行（解決 `docs/v2/59_b_line_390_wireframes.md` 6.5 節記載的「使用者看不出目前在哪一頁」）。
- ⚠️ 側欄**不放**「切回舊版」「前往舊站」之類出口（§6.1）。

### 2.2 手機（390px，單手）

**狀態一：抽屜關閉（預設，內容優先）**

```text
┌──────────────────────────────────────┐
│ ≡   🌍 市場與趨勢 › 市場總覽          │  ← 固定頁首列：≡ 與「目前在」
├──────────────────────────────────────┤
│ 資料截至 ‹MM-DD›                      │
│ ① 結論 …                              │
│ ② 關鍵數字 …                          │
└──────────────────────────────────────┘
```

**狀態二：抽屜開啟，第一層（五類）**

```text
┌──────────────────────────────────────┐
│ ✕  選擇分類                           │
├──────────────────────────────────────┤
│ 🌍 市場與趨勢        ◀ 目前     ›    │  ← 每列高度 ≥ 48px、整列可點
│ ⚖️ 資產配置                    ›    │
│ 💼 我的持股                    ›    │
│ 🔍 找基金                      ›    │
│ ⚙️ 設定                        ›    │
└──────────────────────────────────────┘
```

**狀態三：選了分類之後，第二層（該類子頁）**

```text
┌──────────────────────────────────────┐
│ ‹ 分類    💼 我的持股                 │  ← 「‹ 分類」回第一層（不是回舊版）
├──────────────────────────────────────┤
│ ● 持倉體檢（整頁）          ◀ 目前    │
│ ○ ‹區段跳轉 1›                        │
│ ○ ‹區段跳轉 2›                        │
└──────────────────────────────────────┘
        點任一項 → 抽屜關閉 → 進入該頁（狀態一）
```

- 手機點擊數：同分類內換子頁 ＝ ≡（1）→ 子頁（2）；跨分類 ＝ ≡（1）→ 分類（2）→ 子頁（3）；**只有 1 個子頁的分類，點分類即直達 ＝ 2 次**。**【推論】** 這與客戶「桌機 ≤2 次」的要求不同（手機多一次開抽屜），需客戶確認可接受（§8 小題 4）。
- **沒有任何一個畫面出現「切回舊版」**；每個抽屜狀態都有明確的「關閉」或「返回上一層」，沒有死路。
- 抽屜打開時，目前分類預先展開在第一層列的下方（若實作選「同畫面展開」而非「drill-in」，狀態二與三合併；**兩種排法擇一屬實機驗證後的實作細節**，本草稿推薦 drill-in，因 390px 單手、避免長清單捲動）。
- **【未驗】** Streamlit 原生側欄在 390 寬的實際行為（是否自動收成抽屜、換頁後是否自動關閉）本組**沒有實測**（`docs/v2/58`／`59` 也記載未實測）。

## 7. 對現行路由、`st.navigation`、測試、深連結的影響

### 7.1 現行五頁路由（【事實】）

`ui_v2/app_preview.py`：`PAGES`（`(url_path, 頁名, 函式)` 五列）→ `main()` 以 `st.navigation([st.Page(func, title, url_path, default=首頁)…])` 註冊並 `.run()`；`st.sidebar.info(PREVIEW_NOTE)` 是側欄唯一自訂內容；每個 `page_<slug>()` 第一句呼叫 `_on_page(slug)`（換頁時 pop `_PAGE_STATE_TO_DROP`）；`_settings_page()`／`_page_links()` 以同一組 `PAGES` 再建 `st.Page` 給 `st.page_link`。

### 7.2 深連結／路徑（【事實＋推論】）

- `url_path`（`mkt`／`hld`／`exp`／`alo`／`set`）同時是：書籤、OAuth `redirect_uri` 落點（`/set`）、`st.Page` 雜湊來源（Streamlit 以 `url_path` 算頁雜湊，`st.page_link` 驗它與已註冊頁一致；【事實】`streamlit/navigation/page.py::_validate_registered_page` 與 app_preview 檔頭說明）、以及 AppTest 的 `_page_hash`。**五個 url_path 一律保持不變**。
- 示範／情境用的 `?scenario=`、`?savefail=` 只在示範模式有效（`ui_v2/<頁>/page.py` 的 `_pick_scenario`），與導覽無關。
- 登入暫態的 `code`／`state` 走 `st.query_params`（`ui_v2/set/source.py`）；殼層不得吞掉或改寫 query params。
- 若日後拆頁（方案 B）新增 url_path，**所有新路徑必須也在 `st.navigation` 註冊**（可用 `visibility="hidden"` 不出現在原生選單；【事實】docstring：hidden 頁仍可被 `st.page_link`／`st.switch_page` 到達）。

### 7.3 `st.navigation` 能不能表達兩層導覽？（本節是本草稿最重要的技術判斷）

**驗證方式**：`requirements.txt` 宣告 `streamlit>=1.59.1,<1.60.0`（【事實】已讀該檔）。本機 repo 工作樹沒有安裝 streamlit；本組在**先前 session 留下的 scratchpad venv**（`…/scratchpad/venv/lib/python3.13/site-packages/streamlit-1.59.2.dist-info`，不是本組安裝、也沒有 pip install）找到 **1.59.2**，**直接讀其原始碼與 docstring**（`commands/navigation.py::navigation`、`navigation/page.py::Page`）。1.59.2 落在宣告範圍內，但**部署環境實際版本本組未查**（【未驗】）。

| 能力 | 結果 | 依據 |
|---|---|---|
| `pages` 為 list | 扁平一層頁清單 | 【事實】docstring |
| `pages` 為 `{分組標題: [頁…]}` | **側欄**：分組標題＋該組全部頁**同時展開**（不是「選了才出現」）；**頂部**：每組是可收合下拉 | 【事實】docstring |
| `position="top"` | 導覽在頁首；dict 分組變下拉 | 【事實】 |
| `position="hidden"` | 不畫導覽，頁仍註冊可路由 | 【事實】 |
| `expanded` | 頁數 **>12** 時預設只顯示 10 頁＋「View X more」 | 【事實】docstring |
| `st.Page(visibility="hidden")` | 頁註冊但不出現在原生選單，仍可被 `st.page_link`／`st.switch_page` 到達 | 【事實】docstring |
| **「第一層固定、第二層只顯示目前類的子頁」** | **原生無此元件** | 【推論】由以上列舉推出（無對應參數） |

**判斷**：
- **原生 `dict` 分組（側欄）**＝「五個分組標題＋全部子頁一次列出」。若第二層真的拆成約 18 頁，**超過 12 頁就觸發「View X more」收合**，且第二層不是「只顯示目前類」。**不滿足 D1。**
- **原生 `position="top"`＋dict**＝頂部下拉，兩層成立，但**不是固定側欄**，與客戶指定的「桌機固定第一層側欄」不同；手機行為本組未驗。**可作為方案 C（折衷）。**
- **完整 D1** ＝ `st.navigation(..., position="hidden")` ＋ 在 `st.sidebar` 自己用 `st.page_link` 畫兩層（【推論】可行：`st.page_link` 在 sidebar 內可用、同 session 換頁）。代價：自繪目前頁標示、自繪手機抽屜行為依賴原生側欄的收合機制（【未驗】）。

### 8.2 AI 總管推薦

**推薦方案 A。** 理由：(1) 客戶要的是「長期導覽殼層」，殼層可以獨立於頁內結構先落地；(2) 本草稿的盤點顯示客戶範例子頁**大多沒有對應的獨立頁**，現在就拆頁是在「用導覽需求反向改造頁面結構」，違反 `PROJECT_RULES.md` 13.2「UI 改版以使用者任務與資訊層級為理由、不以程式比較好接為理由」；(3) A 不碰 44 內文、不碰 Active Sheet／OAuth／唯讀護欄，可逆；(4) 客戶看過 A 的實機（桌機＋390）後，可**逐類**決定哪一類值得拆成真子頁（走方案 B 的解凍 Gate）。

**不論選哪案，以下四個 ⬜ 不會出現在導覽**：台股趨勢、國際趨勢、風險觀察、再平衡（理由見 §3.2）。若客戶要其中任何一個，是**新功能需求**，走各自的 Decision Gate，不是導覽問題。
