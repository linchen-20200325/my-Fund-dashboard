## §0 用途與位階

- **用途**：把散在交接本、驗收指南、證據目錄裡「仍開著」的條目逐條編號（`BL-####`），每條附短摘要與出處指標。**詳情不搬**：要看原文、稽核經過、實測指令，照「出處」欄回到原處讀。
- **位階**：本檔是索引，不是規格、不是裁示紀錄、不是授權。與 `CLAUDE.md`、子法 1 `docs/v2/CONSTITUTION.md`（自 2026-10-16 起須併讀正式修正案 #8 `docs/v2/57_amendment_8_directional_judgment.md`，`DEC-2026-10-16-14`）、凍結 SSOT `docs/v2/44_fund_ui_ssot.md` 牴觸時，以它們為準；本檔任何一列都不得被引用為「已核准」或「已查證」。

## §2 新增與關閉規則

1. **必填欄位**：BL-ID、狀態、類別、發現時間、問題、出處（evidence／source）、blocking、prerequisite、下一步、需客戶裁示。不知道的寫「未記載」，不得留空、不得猜。
2. **狀態只用**：`open`／`blocked`／`待客戶裁示`／`待確認`／`deferred`；關閉時改為 `closed`。`待確認` 必須寫出判斷不了的理由。
3. **類別只用**：bug／data gap／tech debt／research／UX debt／deferred improvement／source-quality／architecture debt／future validation／governance。
4. **ID 不重用**：新條目接在目前最大號之後；合併、撤銷、關閉的號碼都不回收。
5. **關閉不刪列**：改狀態為 `closed`，在「下一步」欄寫關閉依據（PR／commit／裁示出處）與關閉日期；被推翻的舊表述照 `CLAUDE.md` 體例加刪除線保留。
6. **新發現的去處**：bug／data gap／tech debt／research → 本檔；客戶裁示 → `docs/DECISIONS.md`；位置／下一步／blocker → `docs/HANDOFF.md`；正式產品規格 → 對應 SSOT（例 44）；evidence → `docs/evidence/` 等可追溯位置；架構分層待判定 → `EXCEPTIONS.md` §8.3.P（依憲法程序）。
7. **有時間窗的條目**：在「下一步」欄寫到期日，並加進 §4 快速索引〈有到期日〉。
8. **全稱句與計數**：寫「只有 N 處／全部是 X」前先想能不能被一條 grep 推翻；會漂移的數字附量測日與 SHA。
