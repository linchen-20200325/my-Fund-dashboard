# New UI2 深色／淺色切換：後續需求登記（2026-11-11）

> **性質**：客戶需求要點的 docs-only 登記，供正式 DEC／BACKLOG／HANDOFF 收斂；非深色模式施工授權、非已核准之 UI 設計 SSOT。本文件在 PR 合併前不代表 main 的正式決策。來源：客戶在 ChatGPT 對話詢問雙模式切換後，於提出「下一階段正式需求」時回覆「好 那請繼續」；以及客戶於 2026-11-11 對 G3／G6 施工與雙模式時序的裁示，已登記為 `DEC-2026-11-11-01`（`docs/DECISIONS.md`）。以上客戶說法皆為**要點轉述，非逐字，repo 內無逐字對話存檔，經總管轉達、本組未見客戶對話本身**；若後續裁示不同，以客戶最新裁示為準。

## 需求及邊界

- **需求**：基金 New UI2 未來應支援使用者手動切換 **☀️ 淺色／🌙 深色**。建議切換入口在 ⚙️ 設定，能記住使用者選擇。預設為目前已核准的淺色主內容＋深色側欄。
- **時序**：G3（B 色票＋A 尺寸）／G6（限縮 UI 容器與 Secondary 頂對齊）的施工授權，**以 `DEC-2026-11-11-01` 為準**（客戶 2026-11-11 裁示，要點轉述），範圍僅限 `ui_v3` 對 🌍 市場頁的樣式調整；該施工批由另一個 PR 進行，**本文件不記載其完成、CI 或 QA 結果**。本文件與 `DEC-2026-11-10-07`（只授權 G3／G6 文件提案）的關係：施工授權僅來自 `DEC-2026-11-11-01`，本文件不是授權來源。不要在該批進行中擴大施工範圍；雙模式獨立做下一階段設計／技術驗證與 Decision Gate。
- **深色值**：暫無獲核准的 dark token／實測對比／正式切換實作；不得直接將 `.streamlit/config.toml` 換成 dark，或把 G3 的 B 色票誤認為深色主內容模式。
- **與既有深色相關記載的關係（S1）**：token 提案 §A.9（`docs/evidence/fund_newui2_market_token_and_wireframe_proposal_2026_11_10.md`）的深色對比表是**研究備註，不是候選**，其色值為假設示例，且該節自述深色主內容的實際渲染未測（NOT VERIFIED）；`DEC-2026-11-10-07` G2 維持淺色主內容＋深色側欄，深色版本只可研究與提案；`DEC-2026-10-27-09`（視覺 theme）同為淺色主內容＋深色側欄。因此日後若要讓**主內容**變深色，須另立新 DEC 並明確 supersede 上述相關裁示，本文件與 `DEC-2026-11-11-01` 都不構成該 supersede；目前既有的「淺色主內容＋深色側欄」維持不變。
- **儲存策略**：偏好可持續記住選擇，但是否採 Streamlit session、瀏覽器儲存、設定檔或其他方式，以及跨裝置／登入／Active Sheet 的語意尚待技術盤點與客戶裁示；不得假設保存能力或偷偷新增雲端寫入。
- **驗收條件（待細化）**：兩模式都要維持字色／狀態色／邊線之對比與文字＋符號提示；390／768／1280 無橫溢、切換可用、首屏預算不變、資料顯示與金融語意一致；須各有瀏覽器級證據並計畫真機／Cloud 驗證。缺資料不可用 0、neutral 或 safe 取代。
- **硬邊界**：不改基金 IA、金融公式、`STATUS_TONES` 映射、FRED、資料契約、FX Gate、OneBrain、`ui_v2` 或正式入口；BL-0545 的唯一 NEXT 不變。

## 下一階段候選方案（三選一，非施工）

| 方案 | 範圍 | 正確性／風險 | 速度／Token |
|---|---|---|---|
| A 固定淺色 | 不提供切換 | 最低風險，但不滿足新需求 | 最快／最低 |
| **B 手動切換（推薦）** | 淺色預設；設定頁日／夜切換；適當保存選擇 | 中風險，需原生 Streamlit／自繪 HTML 協調與無障礙驗收 | 中／中 |
| C 跟隨系統＋手動覆寫 | B 加自動偵測及優先權 | 最高風險，增加跨裝置及狀態契約 | 較慢／較高 |
